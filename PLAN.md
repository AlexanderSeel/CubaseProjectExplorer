# Feature roadmap

Updated: 2026-10-31

This plan lists open product outcomes, not completed-work history or test logs. See [README.md](README.md) for current features, [UX_MANUAL_TEST.md](docs/UX_MANUAL_TEST.md) for hands-on acceptance, and the [2026-10-31 implementation snapshot](docs/research/IMPLEMENTATION_VALIDATION_2026-10-31.md) for dated validation evidence.

## P0 — Reader correctness and evidence

- [ ] **Build a versioned Cubase validation corpus.** The user authorized read-only analysis of the local library and song collection; no originals were changed and no private project data was added to the repository. A bounded metadata sample contains Cubase SX and Cubase 5–15 saved-by text, including CPR/BAK records from Cubase 10–15. Size-bounded CPR/BAK samples were read and compared with the v15 ASM: observed `MMidiTrackEvent` revision 3 in Cubase 10–13 examples and revision 4 in 14/15 examples; `MMidiNote` revision 1 in selected 11–15 backups/projects; and older `MAudioTrackEvent`/`MAudioTrack` revisions in selected 10/11 files. CPRs labeled Cubase 14.0.10 appeared in both RIFF and RIF2, so framing must follow the file signature rather than the release string. A Cubase 13.0.40 sample reached the 10,000-note bound and was marked partial. This confirms cross-generation records reach the reader and v15 callback gates are relevant; bounded samples do not establish a release-wide schema. Continue stratifying representative files and compare interpreted fields with Cubase-visible state. Do not commit private projects.
- [ ] **Read native projects consistently across generations.** Validate RIFF/RIF2 framing, byte order, chunk bounds, compression, nesting, references and crash-backup behavior. Project Analyze re-runs the reader and refreshes the selected project’s audio/MIDI views; supported CPR note, audio-path, mixer, stored plug-in UID/name, and Cubase-15-ASM-backed track/lane class observations are shown in their relevant workflows with source offsets. Track serializer version, body size and header encoding are now attached only when the bounded arrangement scanner and archive inventory agree on exact class name and header offset, and are revealed in technical details. The reader follows Cubase 15 registrations through MMidiTrackEvent, MAudioTrackEvent, MInstrumentTrackEvent and APluginSlot serializer callbacks; matching bounded track class headers are presented as recognized serialized classes, not the blanket “Unverified CPR record.” A deeper callback pass confirmed that the v15 binary contains backward-compatible class-revision branches: MMidiTrackEvent gates fields across revisions 0–4, MMidiNote revision 0 omits a byte added by revision 1, MAudioTrackEvent revision 0 omits its later auto-fade child, and the PAppVersion path has a legacy fallback when version metadata is missing. The arrangement scanner now preserves class revision through note-record parsing and uses the known revision 1 MMidiNote layout only; other revisions remain raw and produce a reader limitation. Further revision-specific semantics and mapping to Cubase 10–14 releases still require implementation and comparison with known-version project fixtures. Typed UID/name property matches are shown as stored plug-in fields found. Extracted names/visibility/hierarchy, plug-in identity/format/owner/state, MIDI timebase and signal routing remain unresolved until independently validated across versions. Preserve bounded structural and token evidence for unsupported files, and show malformed, unsupported, unknown and field-specific candidate data distinctly.
- [ ] **Establish native project structure field by field.** Verify track identity/hierarchy/order, plugin instances and ownership, MIDI, tempo, mixer, sends, routing and logical I/O against controlled Cubase projects before presenting them as confirmed. Native signal flow reads supported OwnInputBus/Bus UID, InputBusValue, OutputBus/Value, OutputBusValue, per-slot send destinations and the ASM-backed `postInsertsPreFader` property. The diagram links indexed insert slots to a channel output stage, then traces resolved bus/FX/output endpoints; insert-position values and saved EQ values remain individually inspectable without inventing EQ defaults, curve shape, or send tap order. Source paths, offsets, candidate evidence and unresolved bus IDs remain visible. This is a reader interpretation from bounded CPR fields and Cubase 15 ASM leads, not a version-independent signal model. Validate field grammar and each relationship across Cubase generations.
- [ ] **Complete native MIDI as a usable feature only after validation.** Confirm note ownership, clip placement and timebase against Cubase 10–15 exports before normalized CPR timing or Standard MIDI export is enabled.
- [ ] **Harden readers for untrusted and unusually large projects.** Differentially test malformed CPR, ZIP/XML limits, duplicate IDs, cancellation, partial files and large inputs. DAWproject `project.xml` and `metadata.xml` now use forward-only `XmlReader` parsing, avoiding a retained `XDocument` plus normalized records; XML remains capped at 16 MiB, depth at 128, archive entries at 5,000, and normalized collections have explicit item limits. A synthetic 100,000-note archive passes. The reader still retains normalized results in memory, and no user archive matching the reported 10–14 GB process growth was available; profile a representative archive and trace the owning allocation before declaring the memory issue fully resolved. Keep exports scoped to declared fields and verify nested clips, automation, device state and MIDI timing with genuine exports.

## P1 — Core desktop workflows

- [ ] **Finish Windows acceptance for the workspace.** Review visible startup with large/unavailable databases, including fallback to the local app-data library while retaining an unavailable configured location; review the dashboard, project report, in-app information overlays, status-bar background progress/cancellation, saved scan-type settings, navigation and failure/loading states at narrow/wide sizes, 100–200% DPI, light/dark/high-contrast themes, keyboard-only and UI Automation. Follow [the manual checklist](docs/UX_MANUAL_TEST.md).
- [ ] **Make large libraries and scans complete predictably.** Startup project hydration now filters saved rows by the same CPR/BAK/DAWproject selection used for discovery; disabling a type retains its database records but avoids hydrating them into the workspace. Desktop scans process one file at a time and retain compact browser summaries plus separate asset indexes rather than all full snapshots/routing arrays; exact checksums are skipped for files above 1 GiB. Scan document/index upserts are split into 32-record batches; cancellation is honored between batches, and an idle end-of-scan `wal_checkpoint(TRUNCATE)` reclaims the journal while a concurrent reader safely defers truncation. On 2026-10-31, the configured `D:\Cubase\cubase-library.db` measured 3.46 GB with a 3.73 GB WAL while the existing app process reached about 20 GiB working set and became unresponsive; its selected scan types were CPR and BAK, with DAWproject disabled. This points to a large-library hydration or scan-save path, not proof that excluded DAWproject source files were opened. These changes need an isolated run against that database to verify actual memory and WAL behavior. Prior read-only measurements against a different 3,436-record database (423 MB SQLite file) measured browser loading at 12–15 s / 484–516 MiB peak working-set growth and plugin statistics at 5.5–6.5 s / 98–139 MiB growth. The earlier database contained 954,828 serialized plugin references (about 323 MiB); compacting/search-indexing the plugin corpus is still required. Verify scan/rescan, cancellation and completion for large libraries and projects without tying up the UI.
- [ ] **Keep library browsing responsive at realistic scale.** Measure search, filtering, grouping, sorting, card/detail switching, navigation history and exports on large indexes; preserve selection and row-action behavior. The Studio I/O graph now offers a movable full forward-chain window from MIDI/media through track, inserts, channel output, buses/FX and destinations when links exist. Complete live visual acceptance of the native routing graph, unresolved bus endpoints, processing chain and source-detail windows with populated CPR files. Review the new recognized-class and stored UID/name wording in the live project overview, Tracks & Channels, Plug-ins, dashboard and report; this wording has passing model tests and builds, but no screenshot review has been completed. Model tests and successful builds do not complete that visual review.
- [ ] **Complete project-to-media workflows.** The renamed **Studio map** gives musicians a track-to-effects/bus/output view and a separate media handoff; it describes saved versus interpreted connections in plain language. The Audio and MIDI pages now inspect the currently open project when selected and do not automatically hydrate the whole project library on page entry. Audio opens scoped to the active project, with a deliberate project selector for broader browsing. Tracks & Channels offers **Find track audio** from each row, joining export media by declared TrackId and CPR path observations by exact enclosing-track offset (or a unique name-only hint when no offset exists). MIDI separates note browsing from index activity. Native note parts sharing a candidate enclosing track byte offset are grouped under a possible track while retaining selectable parts, notes, and source offsets; missing offsets stay in an unassigned group. These groups are structural reader interpretations, not confirmed Cubase ownership. Audio and MIDI show stage/current-project/count/elapsed feedback, cancellation retaining partial results, and bounded background filtering. Validate these choices on large libraries, partial/error data and navigation, plus audio playback/waveforms, media collection/export and project-scoped actions with confirmed references. Native CPR path observations are surfaced in Audio; keep ambiguous paths unavailable as export/collect references until ownership is validated. Populated MIDI was inspected before this tab/grouping update; re-review MIDI and Studio map at narrow size, varied DPI, keyboard, and light/dark/high-contrast themes.
- [ ] **Make information pages useful at a glance.** Project reports open with a session snapshot and focused tabs for arrangement, audio/MIDI, connections/timeline, and reader evidence instead of one long stack of detail lists. Each bounded list remains reachable and Markdown retains the complete report. Recheck populated and empty states, keyboard/accessibility semantics, and responsiveness on large projects.
- [ ] **P1 — Professional UI/UX redesign.** User task: understand a project’s musical contents and decide what to inspect or do next without reading parser jargon. The shared page frame keeps title/context and page actions in a consistent header; the shared palette, spacing, cards, controls and headers have been lightened for a calmer Fluent desktop feel. The Tracks grid filters/searches the friendly displayed track/type labels and substitutes stable type-based names for blank/undefined/unnamed native values; low-level source fields remain behind `(i)`. The **Studio map** label and introduction explain the musician's task; graph hover text is limited to connection names while exact evidence is on the selected node's info action. Audio and MIDI inspect the active project only on page entry; broader library work stays an explicit Analyze action. Audio opens scoped to the active project with a deliberate all-project selector. Plug-in details offer **Search KVR**, which opens a plugin-name search restricted to KVR product pages, or a saved KVR product link if one is available. One shared **Analyze** workflow opens/re-reads a project or rebuilds the selected project/library scope; status bar progress remains the feedback surface. Audio preview draws a seekable WAV waveform with player transport. Plug-in details lead with artwork, maker, session locations, and catalog description; MIDI note rows show pitch class with MIDI number (without assuming octave naming), saved position/length, velocity and channel. Track/part hints use musician-readable labels; byte offsets, source layouts and parser ownership notes stay in `(i)` / Evidence & source. A Help & reader FAQ holds technical terms and open reader questions. Acceptance still pending: full populated/empty/error screenshot review, narrow/wide layout, 100–200% DPI, light/dark/high-contrast, keyboard/UIA, dialog focus/close/scroll, and consistent toolbar/action hierarchy across every page. No visual approval is claimed from a successful build.
- [ ] **Finish calendar and database administration workflows.** Validate unknown/stale file dates, transfer/merge behavior, cleanup, compact, locked/unwritable failures, paging and keyboard use.

## P2 — Studio inventory and comparison

- [ ] **Improve plug-in inventory and catalog trust.** Project plug-in details offer a saved-catalog assessment, a name-targeted KVR product-page search (or saved exact product URL when available), and a catalog grab. The grab checks saved KVR entries first, then the fetched newest-products listing; it imports only a unique punctuation-normalized exact name (preferring an exact known vendor), and otherwise explains ambiguity/no result without importing a similar product. Imported rows retain KVR source/link metadata. Catalog assessments and KVR records remain advisory, not proof of project identity or installation. KVR's official product page exposes a “Search for plugins, brands…” field, while the app currently opens a search-engine query restricted to KVR product pages because the page's search form does not publish a stable direct query URL in its rendered page; revalidate that route and review the workflow visually. Still validate local VST2/VST3 metadata, CID associations, artwork and dependency preflight without executing plug-ins or claiming metadata proves loadability; confirm catalog source terms, attribution, aliases, vendor conflicts, offline imports and duplicate handling.
- [ ] **Strengthen DAWproject comparison.** Validate moved/duplicate tracks and plug-in instances, missing IDs, ambiguous ownership, sends, routing and enabled-state differences against genuine exports.
- [ ] **Improve studio diagnostics from verifiable data.** The graph displays readable native insert slot names, typed EQ values, sends, bus/group/FX nodes and output references where the current bounded reader finds them; full state blobs, sidechain semantics, precise send levels/tap timing, EQ defaults/placement and physical I/O remain future evidence work. Keep hardware state unknown until confirmed.
- [ ] **Add a safe missing-media locator.** Search only user-selected folders, rank exact hashes above weaker matches, explain ambiguity and export proposed mappings without editing projects.
- [ ] **Keep reports consistent and useful.** Preserve provenance, candidate labels, timestamps, privacy, logical disk size and shared-bundle accounting. PDF output is a later extension.

## P3 — Distribution and scope

- [ ] **Prepare a supported Windows release.** Assess signed MSIX/MSI packaging, prerequisites, upgrades, uninstall, clean-machine smoke tests and checksums. Current distribution is unsigned.
- [ ] **Complete security, privacy and accessibility review.** Cover untrusted CPR/ZIP/XML input, catalog networking/caches, logging, exported paths/UIDs, assistive technology and large-library performance.
- [ ] **Consider pre-CPR `.arr`/`.all` only as a separate format feature.** Require a separately documented grammar and licensed fixtures; do not route these files through the CPR reader.

## Gated — Native CPR writing

No native CPR writer or plugin-deactivation feature is approved. Keep this gate closed until the reader correctness work above is complete and independent Cubase round-trip validation covers each supported version.

- [ ] Verify per-version plug-in instance selection, state encoding, offsets, checksums and preservation of unrelated/unknown bytes using independent fixtures.
- [ ] Validate dry-run diffs, destination safety, rollback/rejection, cancellation and unchanged-source guarantees.
- [ ] Round-trip copies through Cubase across versions; independently verify plug-in state, project integrity, playback, reopen and crash behavior.
- [ ] Only then consider a separate opt-in copy workflow with preview and precise outcome reporting. A byte-identical safety copy is not a plugin-disabled project.
