## Current validation snapshot

- The MIDI reader/browser batch passes 431 Release tests with private fixtures enabled. Native MIDI observations cover bounded RIFF/RIF2 packed MMidiPart streams and variable typed-attribute MMidiNote bodies; the old fixed 112-byte restriction missed Cubase 14's 126-byte examples. Source layouts, raw flags and candidate part/track containment propagate into indexes. A read-only smoke pass over 31 saved-by version hints spanning Cubase 10–14 retained 13,139 candidate notes with unchanged SHA-256 values; two public template.io CPRs parse, and the Cubase 12 XML/CPR independently agree on 2,176 MIDI-track declarations/candidates. See [source review and limits](docs/research/CPR_10_14_PARSER_REVIEW.md). Native timing/ownership/export semantics remain unverified.
- The MIDI page uses source selection, project/part groups, a raw-position note plot, compact sortable note values and a source-evidence popup. Narrow windows use a compact group selector. Live Windows 11 Pro 10.0.26300 review at 192 DPI (200%), dark theme, checked populated 1440×1000 and 1280×720 logical windows, project filtering (11 groups/71 observations → 1 group/14), no results, clearing search, source switching to an empty exported dataset and restoring native data. Keyboard Tab moved search focus to Refresh index; UI Automation exposed names and values. Screenshots/UIA logs remain under ignored `artifacts/validation/midi-source-review/` (`midi-final-wide.png`, `midi-final-narrow.png`, filtered/no-results/exported-empty variants). Light/high-contrast, other DPI settings, full keyboard/screen-reader, database failure/loading and eligible export/playback acceptance remain pending. Source mode selection needed a keyboard fallback in the UIA helper; no full accessibility approval is claimed.
- Both original Cubase 15.0.40 fixture hashes match `docs/CPR_RIF2_TEST_FIXTURES.md`; the controlled MIDI file still exposes 16 note-layout candidates and the empty file exposes none. The 431-test Release run includes detailed ARCH bounds, references, class versions, unknown classes, malformed lengths, cancellation, aggregate safety limits, selectable scan-type discovery, a DAWproject scan-concurrency guard and a synthetic 25,000-note DAWproject. Five pre-existing xUnit2031 analyzer warnings remain.
- The new user-provided IDA assembly export identifies the same executable SHA-256 as prior analysis. Complete selected procedures confirm independent inherited class-version gates, u16 flags and u32 attribute counts; raw nonzero flags and zero-attribute class records have regression coverage. `scripts/inspect_cubase15_ida_export.py` extracts bounded procedures from a fixed mapped snapshot, validates the header hash and reports incomplete targets. Real extraction, synthetic extraction and wrong-hash refusal passed. The growing full assembly and IDA databases are ignored and were not modified or staged.
- A follow-up bounded IDA review confirmed the Cubase 15 `MTimeSignatureEvent` fixed prefix (one u64 plus six u16) followed by named attributes for class version >1. The inspector now exposes only the exact 20-byte prefix for version 2 as anonymous raw field candidates, with byte offsets and bytes preserved; attributes and musical meaning remain unknown. The maintained IDA extractor now includes bounded reader/writer targets for time signatures, markers and tempo tracks. Marker parsing and variable-count tempo arrays remain open because their helper/per-item attribute boundaries are not yet established.
- Verification after the time-signature candidate addition: 431 Release tests pass (five pre-existing xUnit2031 analyzer warnings); Uno Desktop and CLI Release builds pass with zero warnings/errors. Build outputs are under ignored `.build-check/20261031-ida-signature/`.
- [Further static analysis](docs/research/CUBASE15_SERIALIZER_ANALYSIS.md) of the unchanged user-supplied Cubase 15.0.40 executable confirms additional ROOT/ARCH framing, class serialization versions, mode-dependent body sizes and registration-to-reader chains. Actual CLI JSON/Markdown smoke tests inventory all seven ARCH streams in each controlled fixture: 225 and 342 class-header candidates respectively, seven anonymous tempo-track raw fields each, no reached inventory limits and unchanged source hashes. Raw fields retain original bits and build-specific provenance. No BPM, tempo map, plugin identity, musical ownership or all-version support is promoted from this evidence.
- Eight additional uncontrolled `D:\Cubase` RIFF samples with saved-by hints SX 3.1.1, 6.5.0, 6.5.2, 7.0.0, 7.0.6, Artist 7.0.1, 8.5.30 and 11.0.10 passed CLI structure smoke checks: 49 ARCH inventories, 26,296 class-header candidates, unchanged source SHA-256 values. It does not verify note ownership, timebase, clip placement, tempo-field units or MIDI export semantics. The two Cubase 15 fixtures do not establish support for older Cubase layouts or native sample-path recovery.
- The user-provided `D:\Cubase` corpus inventory contains 83,123 files (1,159 `.cpr`, 2,368 `.bak`, 65,492 `.wav`, 83.85 GiB total). A read-only pass over 3,527 CPR/BAK files parsed 3,515 and reported 10 not recognized and 2 unsupported. Existing backup/import/path/cleanup/compact workflows remain available. Raw SQL writes and unknown document-type CRUD are intentionally not exposed. Added regression coverage passes; manual responsive/keyboard and lock/failure-state review remains open.
- This batch adds a library-wide Studio Overview, a populated project report, native secondary windows for information/evidence actions, and a modeless progress window for long background work. Startup leaves the shell navigable, database query materialization and scan reconciliation run off the UI thread, scan progress is coalesced, and whole-file checksums report byte progress. The Settings page now persists CPR, BAK and DAWproject scan selections, and those selections filter discovery for both new scans and rescans; existing indexed records are retained when a type is disabled. The DAWproject reader keeps its 16 MiB XML/depth/ratio limits and classifies the bounded XML tree in one cancellable walk; folder scans now parse DAWproject files one at a time to avoid overlapping large XML trees. Synthetic 25,000-note and serialized-scan tests pass; no genuine large DAWproject performance fixture was available.
- Live Windows review uncovered a high-memory startup case in the existing local library: 3,436 stored project documents contain about 416 MB of serialized JSON before deserialization. The newly built preview stayed responsive at the point checked, but the UI capture showed loading had not completed; an older, pre-existing app process was unresponsive and consumed several GB. It was left running to avoid disrupting user state. Database hydration memory/time and the suspected oversized-DAWproject scan therefore remain open performance gates; don't treat background execution alone as proof that these workflows scale.

Dashboard/report layout, native window move/resize/close behavior and detached progress-window behavior have not yet passed a reliable visual interaction review. A build is not visual, keyboard, accessibility, playback or scale approval.
